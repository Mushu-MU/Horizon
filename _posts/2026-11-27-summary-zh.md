### [AMD 专用 llama.cpp 分支优化本地推理](https://devnull.land/amd-specific-llama-cpp) ⭐️ 7.0/10

Hacker News 上出现了一个 AMD 专用 llama.cpp 分支，目标是针对特定 AMD GPU 优化本地大语言模型推理。现有信息只说明它是面向 AMD 硬件的定制分支，未给出支持的具体 GPU 架构、版本号、性能数据或与上游的合入关系。因此，目前更适合把它看作社区探索性的优化路径，而不是 llama.cpp 上游已正式发布的 AMD 支持。

hackernews · julianlam · 11月26日 17:11 · [社区讨论](https://news.ycombinator.com/item?id=50657265)

**「背景」** llama.cpp 的 AMD GPU 支持依赖 ROCm/HIP 后端，而 AMD 的 gfx906 数据中心卡（如 MI50、Radeon VII）目前只在 ROCm 的 nightly 构建中受支持，官方稳定版并未覆盖，因此这类硬件往往需要专门的分支来适配。Hacker News 讨论还提到，这批 2018 年前后的卡拥有 HBM2 高带宽但通用计算能力一般，围绕它们已形成一个针对本地大模型推理做优化的社区。

**「影响」** 对于使用大显存、高带宽但计算能力较弱的旧款 AMD 数据中心卡运行本地推理的用户，这类分支可能提供比通用上游更贴合硬件的优化；采用前应核对分支支持的 GPU 架构、ROCm 版本和量化格式，并注意其可能落后于 llama.cpp 上游。

**「社区讨论」** 评论者 rao-v 回顾称，2025 年初社区发现约 2018 年的 gfx906 数据中心卡虽有计算短板，却能以约 200 美元提供 32GB HBM2 和约 1TB/s 带宽，由此催生了一批针对缺少张量核心和原生 bf16 的 llama.cpp 优化分支。fiddlerwoaroof 则报告在 MI100 上通过将部分 Nvidia 内核移植到 ROCm 获得约两到三倍加速，并称对移植内核做了数值校验；这些均为个人经验，尚未独立验证。

### [朝鲜关联 PolinRider 在 GitHub 仓库植入 Python 加载器](https://thehackernews.com/2026/11/north-korea-linked-polinrider-poisons.html) ⭐️ 7.0/10

与朝鲜有关的 PolinRider 活动被发现在公开 GitHub 仓库中植入一个 58 行的 Python 加载器，位置包括小型 utils 包或 conftest.py；Python 导入该文件后，会读取某个以太坊钱包向自身发送的最新交易，把交易输入数据解码为 JavaScript 并用 Node.js 执行，再借第二个钱包解析 C2，并通过脱离的 node -i 进程运行下一阶段。SafeDep 表示已在 375 个公共仓库、260 个账户中识别到该加载器，且没有证据表明它经 PyPI 或 npm 分发；Apiiro 则估计其出现在至少 7,609 个 GitHub 仓库、2,330 个账户中，并在 2026 年 10 月 27 日至 11 月 6 日向 2,040 个仓库推送了加载器。两家公司的数字差异很大，均属厂商评估，第二阶段的 /0x/cls 与 /0x/ls 载荷具体性质仍不清楚，但以往波次曾安装窃取环境变量、浏览器密码、Cookie 和钱包数据的恶意软件。报道还称该活动可能最早始于 2025 年 2 月，并将 PolinRider 描述为与 Contagious Interview 并行运作的子集群。

rss · The Hacker News · 11月26日 15:13

**「背景」** PolinRider 被描述为与朝鲜关联、与长期活动 Contagious Interview 并行运作的子集群：后者主要通过虚假招聘等社会工程手段入侵开发者，前者则利用已获取的访问权限改写仓库，把开源项目变成恶意代码分发渠道。SafeDep 称相关活动可能最早可追溯至 2025 年 2 月，并发现攻击者此前已在被篡改的 npm 包和 HuntRole 假招聘活动中复用同一个以太坊钱包地址来拉取 /0x/cls 与 /0x/ls 载荷；此次是把这套钱包取址和 Node.js 执行链放进了 GitHub 仓库中的 Python 加载器。

**「对维护者与使用者的直接影响」** 对使用或维护这些仓库的开发者来说，风险在于：克隆并导入、构建一个看起来正常的仓库，就可能触发加载器；恶意包本身并未进入 PyPI 或 npm。载荷被藏在构建配置中数百个空格之后，并保留原作者、提交信息与日期重写提交；AsyncAPI Generator 维护者称，恶意提交在分支上只停留 30–40 分钟便被 force-push 抹去，因此事后查看 diff 可能完全干净。Apiiro 统计至少涉及 2,330 个账号，受害者包括 Neutralinojs、InstaWP Connect、fxhash 等项目；维护者应检查构建配置中的异常空白字符、\`conftest.py\` 与 utils 包，轮换 GitHub token，并留意伪装成 fa-solid-400.woff2 等文件的字体载荷和自动运行的 VS Code 任务。

### [1Password 披露后端入侵：客户数据与源代码被窃](https://thehackernews.com/2026/11/1password-hacked-customer-data-and.html) ⭐️ 7.0/10

1Password 披露，一名攻击者通过入侵员工的 GitHub 企业账号进入部分后端系统，获取了部分客户的姓名、邮箱、账号与用户标识、公钥及部分内部账户元数据，并复制私有仓库源代码、访问 CI/CD 系统。公司称客户密码库、密码、密钥及账户恢复密钥未被访问，服务可用性和产品安全未受影响，但攻击者曾向部分后端服务推送恶意代码。1Password 已禁用涉事 GitHub 账号、撤销被盗令牌、轮换内部凭据并恢复受影响服务，还将邀请和账户恢复邮件中的验证码从六位数字改为十位字符。公司表示受影响用户数量很少并已单独通知，邮件链接中的令牌无法单独登录账户，仍需 SSO 或发送至注册邮箱的验证码。

rss · The Hacker News · 11月26日 10:57

**「背景」** 1Password 是广泛使用的密码管理器；按其说明，用户保险库中的密码和密钥由仅用户本人持有的密钥加密，服务端无法读取。此次事件因此需要区分后端账户信息、源代码与保险库内容：前两者可能暴露，而公司称后者未受影响。

**「影响与应对」** 使用 1Password 的用户应警惕利用泄露的姓名、邮箱和账户元数据实施的定向钓鱼；公司称用户无需更改密码或轮换密钥，因为密码库内容及其保护密钥未被访问。

### [Drupal 警告核心站点接管漏洞正被在野利用](https://thehackernews.com/2026/11/drupal-warns-of-new-highly-critical.html) ⭐️ 7.0/10

Drupal 警告称，Drupal core 的极高危漏洞 CVE-2026-136716（CVSS 评分 N/A）正在被在野利用，并可导致站点接管。该漏洞与 CVE-2026-132165（Fail2Install）相关：在此前修复后，处于异常或不完整安装状态、且 install.php 仍可远程访问的站点继续可能被接管，包括生产站点；界面不会显示这种脆弱状态，已保护安装程序的站点则不受影响。官方修复版本为 Drupal 11.4.14、11.3.23 和 10.6.23；11.0.x 至 11.2.x 及 10.5.x 及以下已停止支持、没有修复。StepSecurity 统计称，约 55,800 个互联网可达 Drupal 站点中，31,500 个运行受 CVE-2026-132165 影响的分支，约 15,000 个仍在已停止支持的 8 和 9 分支；Drupal 建议检查日志中 user 1 的异常改动、确保其邮箱受控并考虑重置密码，更新后运行 update.php，并在所有新旧站点上保护安装程序。

rss · The Hacker News · 11月26日 07:02

**「背景」** Drupal 核心安装器此前被披露存在多个漏洞，CVE-2026-132165（Fail2Install）正是针对这些安装器问题的修复。此次新漏洞的关键在于，该修复未覆盖某些异常或未完成的安装状态，而这些状态无法从用户界面直接识别。

**「影响」** 运维团队不能仅靠 Drupal 界面判断是否安全：在 CVE-2026-132165 修复后仍暴露 install.php 的站点可能已被入侵，且已遭入侵的站点可能不再处于可检测的脆弱状态，因此应审计 user 1 的日志和邮箱控制权。仍在 11.0–11.2 或 10.5 及以下分支的站点没有官方修复，需要迁移到受支持分支。

### [SYS010 借浏览器管理强装扩展窃取邮箱](https://www.bleepingcomputer.com/news/security/sys010-malware-abuses-browser-management-to-spy-on-gmail-outlook/) ⭐️ 7.0/10

据 BleepingComputer 报道，一个通过 Meta 广告传播的新版 SYS01 信息窃取程序（文章标题写作 SYS010）会将浏览器纳入企业式管理，以强制安装可窃取 Gmail 和 Outlook 邮件等敏感数据的扩展。报道称这是该恶意软件的新变种，但未提供扩展名称、受影响的浏览器版本、感染数量或攻击者身份。由于恶意扩展由管理策略强制部署，用户可能不会看到常规的扩展安装提示。

rss · BleepingComputer · 11月26日 11:50

**「背景」** SYS010 是在 SYS01 窃密木马基础上出现的新变种。此次手法滥用了浏览器的企业式管理机制：浏览器一旦被纳入管理，策略就可以强制安装扩展，用户通常无法自行移除，攻击者因此能借该扩展读取 Gmail 和 Outlook 数据。

**「影响」** 对使用网页版 Gmail 或 Outlook 的用户而言，浏览器是否显示由未知组织管理、扩展列表中是否出现并非自己安装的条目，都是可直接排查的迹象；若发现这类情况，应按组织安全流程处理。

荷兰外贸与发展合作大臣 Sjoerd Sjoerdsma 于 11 月 26 日在议会表示，荷兰不会接受美国进一步限制 ASML 对华销售，并反对 MATCH Act 的域外管辖效力；他还称荷兰“不会任人摆布”。该法案由美国两党共同提出，要求荷兰、日本等盟友收紧对华半导体设备出口管制，否则美方将单方面限制其半导体设备；中国约占 ASML 今年销售额的 20%。荷兰正与欧盟委员会协调，并联合德国、法国游说，争取把该法案从美国年度国防政策法案中剔除；外界预计国会 12 月中旬表决，通过的可能性很大。

**「潜在影响」** 若法案通过，荷兰等盟友将面临更严格的对华出口管制，否则其半导体设备可能遭到美国单方面限制；对 ASML 而言，这可能进一步压缩其占今年销售额约 20% 的中国业务。荷兰联合德国、法国在国会表决前推动移除相关条款，正是为了阻止这一域外约束落地。

### [AI 检测之争实为权力之争](https://seangoedecke.com/who-gets-to-decide-if-something-is-written-by-ai/) ⭐️ 6.0/10

rss · Sean Goedecke · 11月27日 00:00

**「背景」** 围绕写作奖得主是否用 AI、作者因手稿被 Pangram 标记而失去合同、以及某条推文是否由人所写，争论每天都在发生。作者认为，单用检测可靠性或“不该扫描他人作品”解释不了反 AI 阵营对检测工具的强烈反感。

**「方案」** 他把问题重述为“谁有权判定，并据此守门”：谁来决定文学奖、考试成绩和公共讨论的准入。作者也试着理解反 AI 者：若把 AI 视为科技业扩张社会权力的一部分，不信任另一家科技公司当裁判就合乎逻辑；过去几十年从社区化流程转向工具化流程，也加深了这种不信任。但他认为，检测工具之外唯一现实替代是社区自判，而据其在 Twitter 上的观察，不用 AI 的人既会漏掉明显的 AI 痕迹，也会把冗长、礼貌的人类文本误判为 AI，因此社区自判往往更糟。于是他的结论是，若真想把 AI 挡在人类艺术与文化空间之外，就应使用最有效的检测工具；若不信任公司，就推动开源方案或由政府自建检测平台。检测可靠性、隐私等争议被他视为次要问题。

**「启示」** 作者的核心结论是，AI 检测争议表面在争工具准不准，实质在争治理权归谁；放弃检测工具不会阻止 AI 内容，反而把判定权交给更不可靠的社区直觉。
